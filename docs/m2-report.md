# M2 前端原型

## 怎么验收

```bash
pnpm db:pull                                # 把 Railway 的数据拉到本机 Postgres（经 SSL）
DATABASE_URL=postgres://localhost:5432/app_radar RO_OUT=apps/web/.dev.vars pnpm db:setup-ro
cd apps/web && pnpm build && pnpm dev:api   # 打开 http://localhost:8788
```

开发时可以另开一个终端跑 `pnpm dev`（Vite，带热更新，`/api` 会代理到 8788）。

验收路径：选国家/地区和品类 → 看榜单（排名变化、标签、快捷筛选）→ 点进 App → 看基本信息、所在榜单、排名和评分走势、评论（星级筛选、低分优先或最新优先、加载更多）、折叠的描述。

## 实现

- **API**：6 个只读接口都在 `apps/web/functions/api/`，参数用 zod 校验。线上缓存 10 分钟（Cache API 加浏览器缓存），本地不缓存。
- **标签阈值**：构建时从 `config.yaml` 读取，由前端计算。
- **筛选条件**：同步到 URL；国家、品类、榜单记在 localStorage 里；日期不记，默认总是最新。
- **走势图**：手写 SVG，没有引入图表库。按 dataviz 规范：线宽 2px，有图例和十字准线提示框，附数据表，用验证过的色板，跟随系统深色模式。
- **评论翻译**：不翻译。中文评论标 `lang="zh"`，其余交给沉浸式翻译自动识别。

## 现在的数据状态

- **榜单**：库里有 11-20、11-21 两天的数据，所以「相对昨天」的变化和新上榜标签已经能显示；「7 天」变化和急升标签要攒够 7 天才有。
- **AI 内容**：简报和摘要要到 M3 才生成，现在页面上显示占位说明。
- **评论**：评论数据有一天多的延迟，所以最新评论是 11-19 的。

## 已知限制

- **本地连的是数据副本**：本地开发用的是 Railway 数据的本地副本，不是直连 Railway。原因是本地 workerd 发不了 TLS，见 DECISIONS.md。
- **同名次的点会重叠**：多个榜单名次相同时，走势图上的点会叠在一起，提示框里会把每个榜单都列出来。
