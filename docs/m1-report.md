# M1 采集入库报告

## 怎么验收

```bash
pnpm install
cp .env.example .env              # 填 DATABASE_URL（本地库即可）
pnpm db:migrate
pnpm pipeline run --stage charts  # 约 4 分钟
pnpm pipeline run --stage apps    # 约 6 分钟
pnpm pipeline run --stage reviews --country us --genre 6007 --chart free --limit-apps 5
pnpm pipeline report              # 各表行数、体积、最近的 job_runs
pnpm test
```

其他参数：`--dry-run`（不写库）、`--country us,jp`、`--genre 0,6007`、`--chart free`、`--max-minutes`。

评论阶段的全量要放到 GitHub Actions 上跑，原因是网页接口对本机（中国 IP）限流更严，间隔 6 秒时 60% 返回 429。Actions 上的手动 workflow `daily` 默认是 dry-run。

### 评论：GitHub Actions dry-run（每个国家一台机器）

| 国家 | 评论范围 | 排除的游戏 | 已处理 | 网页接口 429 | 前 N 个 App 的日均新评论 |
|---|---|---|---|---|---|
| us | 2,037 | 47 | 1,118（限 60 分钟） | 27 次，重试后全部成功 | 未统计（这一轮还没加估算） |
| cn | 1,955 | 52 | 749（限 40 分钟） | 0 | 1,388 |
| jp | 2,036 | 69 | 744（限 40 分钟） | 0 | 674 |

网页接口持续请求的平均间隔是 3.07 秒，每个国家跑完全量约 105 分钟，3 个国家并行，在 Actions 单个 job 6 小时的上限之内。约 3–5% 的 App 返回 404，基本是还没有评论的新 App，已改成不计为错误。

### 本地小范围写库测试

6 个 App 首次回填：48 次请求，入库 816 条。第二轮重跑每个 App 只请求 1 页，碰到已入库的评论就停下，新增 0 条，说明增量和去重都正常。

## 每日数据量估算

| 项目 | 每天 | 每月 |
|---|---|---|
| chart_snapshots | 189 行，约 0.2 MB | 约 6 MB |
| app_rating_daily | 约 15,700 行，约 2 MB（含索引） | 约 60 MB |
| apps | 新上榜的 App，约几百行 | 几 MB |
| reviews（稳态） | 约 5,000–10,000 条，每条约 1 KB（含译文） | 150–300 MB |
| reviews（回填期） | 前约 7 天，每个国家每天回填 300 个 App，最多 160 条/个 | 一次性约 1 GB |

评论量是推算出来的：cn 和 jp 只统计了排名最靠前的约 750 个 App，剩下约 1,250 个排名靠后、评论更少；us 没有统计，估计和 cn 是同一个量级。

## 和 SPEC 的不同（详见 DECISIONS.md）

1. **评论主来源换成了 apps.apple.com 网页接口，RSS 只做兜底。** 这是你授权的方案 2。两边的评论 ID 是同一套编号，可以混用。代价是网页接口没有 App 版本号和有用数，这两个字段只有 RSS 兜底时才有值。
2. **每天抓多少评论的配置改了单位。** 以前是「每天 1 页 RSS（50 条）」，现在是「网页接口往下翻页，遇到已入库的评论就停，每天最多 5 页（100 条）」。
3. **评论范围用你确认过的方案**：核心品类前 50、次要品类前 20，排除游戏，回填每天限 300 个 App。

## 留给后面里程碑的问题

- **M3 翻译量**：稳态下 us 和 jp 每天约几千条评论要翻译，按 DeepSeek 的价格粗算在每天 ¥10 的预算附近，M3 实测后再定。回填期每天会多出几万条，预算控制会把它们顺延到后面几天。建议翻译只覆盖最近 30 天的评论，或者先翻低分评论；这件事到 M3 再找你确认。
- **M5 存储优化**：`apps` 每天整行更新，`description` 这类长文本会被重写，带来约 40 MB 的 MVCC 膨胀，靠 autovacuum 回收。可以优化成只在内容变化时才更新长文本字段。
- **探测还在跑**：`m0-probe` 仍在每 4 小时跑一次，用来观察 RSS 的情况。按计划跑满 2 天，到 11-22 停用。
