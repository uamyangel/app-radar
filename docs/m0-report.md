# M0 接口验证报告

实测时间：2026-11-20，从本机（中国大陆 IP）发出，按 1 req/s 限速，共 264 个请求。
原始数据见 `docs/m0-report.data.md`，复现：`pnpm m0`。

## 结论

| 端点 | 状态 | 说明 |
|---|---|---|
| 旧版 RSS 榜单（3.1 A） | 可用 | 189 个组合全部 HTTP 200，品类筛选和畅销榜都正常 |
| Marketing RSS（3.1 B） | 可用但不稳定 | 6 个组合最终都拿到数据，过程中 502/504/超时频繁，需要较长的重试 |
| lookup（3.2） | 可用 | 单次 200 个 ID 也全部返回 |
| 评论 RSS（3.3） | **基本不可用** | 本机和 GitHub Actions 上都是大多数请求返回空 feed，详见下文 |

## 与 SPEC 的差异

### 1. 评论接口大面积返回空数据（阻塞）

HTTP 200，但 feed 里没有 `entry`，first/last 分页链接为空。对照组是评论量上亿的 App：

- Facebook（us）：14 次请求全部为空
- LINE（jp）：只有第 6 页返回了 50 条，其余全空
- 微信（cn）：第 1、3 页有数据，其余为空

换 UA、换 XML 格式、加随机参数绕 CDN 缓存、把国家写进 query（`?cc=us`）都没有明显改善。同一个 URL 在 20 分钟前返回过 50 条，后来稳定返回空。

**GitHub Actions（海外 IP）复测**（run 44733851231，`scripts/m0-reviews-probe.ts`）：18 个 App 各请求 6 次，非空比例 11%。

- 只有 ChatGPT（us）、Claude（us）、抖音商城（cn）的第 1 页能拿到数据，重复请求 3 次结果一致；它们的第 2、3 页仍然为空。
- Facebook、微信、LINE 等其余 15 个 App 6 次全空。
- 海外请求的 CDN 缓存键里不带国家标记。

结论是 Apple 这一端的问题，和请求来自哪个国家无关。同一个 URL 的结果会持续一段时间不变，本机又见过 Facebook 从 50 条变成 0 条，比较像源站时好时坏、空结果被 CDN 缓存。目前还不知道换个时间重试能否拿到数据，这一点没有验证。

### 2. 榜单条数不总是 100

126/189 个榜单正好 100 条，其余大多在 93–99 之间。异常的有：

- cn 新闻（6009）三个榜单都是 0 条
- cn/jp 购物付费榜、jp 新闻付费榜只有 78–79 条

这些都是 Apple 返回的真实数据，代码按实际条数存储即可。

### 3. Genre ID 全部正确

20 个品类的榜单里，每个 App 的 category 都和请求的 genre 一致（匹配率 100%）。

### 4. 总榜里有大量游戏

免费总榜里没有游戏，付费总榜和畅销总榜里游戏分别占 54–78 和 38–57 个。SPEC 说「不含游戏品类」，又说要保留「全部」总榜，这两条在总榜上冲突了。

### 5. lookup

- **批量上限**：单次 200 个 ID 也能全部返回，URL 约 2.1KB。计划用 100 一批：每个国家约 50 次请求，总共约 3 分钟，没必要冒更大批量的风险。
- **内购信息**：lookup 没有这个字段，SPEC 3.2 列的这一项拿不到。
- **其他字段**：SPEC 要的其余字段都有。jp 抽样的 100 个 App 里有 1 个缺 `releaseNotes`。

### 6. 评论字段

第 1 页没有混入 App 自身信息，但解析时仍会过滤掉没有 `im:rating` 的条目。

- **有用数**：有，字段是 `im:voteSum` 和 `im:voteCount`。
- **排序**：拿到的数据严格按时间倒序。
- **分页**：第 11 页返回 400，分页上限确认是 10 页。

### 7. 数据规模比 SPEC 预想的大很多（影响评论采集方案）

| | us | cn | jp |
|---|---|---|---|
| 当天榜单去重 App 数 | 5,349 | 4,984 | 5,392 |
| 各榜前 50 去重 App 数（评论采集范围） | 2,718 | 2,560 | 2,747 |

评论采集范围合计约 8,000 个 App，每个 App 每天抓 1 页，按 1 req/s 要 2.2 小时。新 App 首次进入时还要回填 3 页，首日约 24,000 次请求、6.7 小时，超过 GitHub Actions 单个 job 6 小时的上限。

### 8. 中国区数据

从本机请求 `country=cn` 一切正常。GitHub Actions 上请求 cn 的榜单正常。
