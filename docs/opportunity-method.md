# 产品机会分析方案（v3）

2026-11-28。替代 v2 里「从需求聚类出机会卡」的做法。需求和提法保留，作为证据库。

## 1. 这个领域最会做的人怎么做

做这件事最强的，是三类人方法的合体：

- 应用市场数据公司的研究员（Sensor Tower、AppMagic、Appfigures、data.ai），每天看下载、收入和排名的变化；
- 系统挑品类的应用工作室，包括收购老 App 再重做的公司，以及按关键词批量铺产品的应用工厂；
- 靠 ASO 挑细分市场、一个人做到稳定收入的独立开发者。

他们的共同点是：先看钱和用户正在往哪里流，再拆解赢的人为什么赢，最后才找自己的切入点。差评用来解释现象和找切口，不用来发现机会。

### 他们用的工具

| 用途 | 工具 |
|---|---|
| 下载量和收入估算 | Sensor Tower、AppMagic、data.ai、Appfigures |
| 关键词热度和竞争度 | Apple Search Ads 热度分、AppTweak、Astro |
| 排名历史和排名变化 | 同上，或自己每天存榜单 |
| 竞品商店页、版本历史、内购价格 | 商店页本身，加上述工具的历史快照 |
| 获客方式 | Meta 广告库、TikTok Creative Center |
| 变现基准 | RevenueCat 的订阅应用年度报告 |

### 他们的分析框架：按顺序回答五个问题

1. **钱在哪里，有多少。** 看场景里的收入池（畅销榜位置）和用户量（免费榜位置、下载增速）。没人付钱、也没多少人用的场景，后面几步不用看。
2. **这个市场进得去吗。** 看近两年的新 App 有没有挤进前列，以及头部 App 的年龄、更新频率和集中度。前十名五年没换过的市场，通常是被网络效应或品牌锁住了，不碰。
3. **最近什么在变。** 看谁在快速上升、谁在往下掉，上升的 App 有什么共同点。常见的原因有五种：新能力（比如端侧 AI）、新人群、新获客渠道、新的收钱方式、从别的国家搬过来。
4. **赢的人为什么赢。** 拆四件事：
   - 定位：商店页标题、副标题、第一张截图在承诺什么；
   - 人群：评论里是谁在用，从哪个 App 换过来；
   - 变现：价格、订阅还是买断、有没有试用；
   - 获客：靠哪些关键词被搜到，广告素材长什么样。
5. **我们的切口在哪。** 常见的切法有四种：搬到还没人做的市场；切出更窄的人群；换一种收钱方式；去体验更差的在位者那里抢用户。每个切口都要附上获客路径和粗略的单位经济，比如获客成本和每个用户能带来的收入。

做之前，他们会先用小成本验证，比如买几个关键词广告、或者放一个落地页看转化，并提前写好什么结果出现就放弃。

## 2. 我们有什么、缺什么

| | 有 | 缺 | 替代办法 |
|---|---|---|---|
| 用户量 | 每日评分数（`app_rating_daily`，11-20 起） | 下载量估算 | 用评分增速代替。评分数大致随下载量增长，但各 App 比例差很多，只在场景内或同龄 App 之间比 |
| 收入 | 畅销榜前 100（3 国 × 21 品类，每天） | 收入估算 | 只用畅销榜的相对位置，不算金额 |
| 市场结构 | 上架日期、版本日期、开发者类型、场景标签 | 排名历史只有 9 天 | 先用上架日期和当前排名，等榜单攒到 4 周再看排名变化 |
| 定位 | 标题、简介、截图链接、价格 | 副标题、内购价格表 | 之后从商店页补抓，需要先验证接口 |
| 人群和抢谁 | 评论、已提取的提法（包括提到的竞品） | | |
| 获客 | | 关键词热度、广告素材 | 暂时不做，卡片里只写能从商店页看出的线索，并标明是推测 |

## 3. 实验已经说明的事

- 从评论抱怨出发，推不出机会在哪个场景。模型推理（包括加上能力清单和任务链）也分不出哪个场景会出新爆款，给出的多是显而易见的套壳。
- 新 App 上架头 90 天就起量，是真实但偏弱的信号。这类 App 后来跑出来的概率约为平均的两倍，提前量大约 3 个月（`.experiments/vel/PLAN.md`）。

所以，"在哪里"交给数据，"为什么、怎么切"交给模型。

## 4. 方案：机会从数据事件出发

### 第一步：找事件（只用 SQL，不调 AI）

- **E1 新 App 起量。** 条件：
  - 上架不超过 365 天；
  - 排除大公司、平台、品牌和内容方（沿用 `developers.type`）；
  - 日均评分增速在同国、同龄 App 里排在前列，而且最近 7 天还在涨。

  要排除继承旧版评分的重新上架 App：这类 App 上架没几天就有几千条评分。

  只用上架日期和当前评分数（日均增速 = 评分数 ÷ 上架天数），现在就能出第一批名单。等 `app_rating_daily` 攒够 2–3 周，再加上近期增速。
- **E2 跨国空档。** 场景是跨国共用的。同一个场景，在某国有 E1 事件，或者头部是独立开发者在赚钱，而另一国同场景的前列没有对应产品。
- **E3 在位者掉队。** 同场景里，头部 App 排名持续下滑、长期不更新，同时有新 App 在上升，这就说明了谁的用户在被抢。这需要榜单历史，等攒够 4 周再做。

### 第二步：拆解事件（调 AI）

每个事件生成一张卡片，回答框架的五个问题：

- **场景和市场：** 这个场景的收入池在哪个位置；市场开不开（近两年挤进前列的新 App 数量、头部 App 的年龄）。
- **赢家拆解：** 做给谁；怎么定位（引用商店页原话）；怎么收钱；可能怎么获客（标明是推测）。
- **抢了谁的用户：** 评论里提到从哪个 App 换来，或者同场景里谁的排名在下滑。没有证据就写"没有证据"。
- **为什么是现在：** 新能力、平台变化、季节或外部事件、从别国搬来。
- **我们的切口：** 最多两个。每个都要写清人群、定位、和赢家的差别、获客路径、在位者为什么不会马上跟进。
- **风险和放弃条件。**
- **证据：** 评论原文和提法，只作为证据引用。

### 第三步：预测日志

每个事件记录触发时的数据。30 天和 90 天后自动复核：这个新 App 是否还在涨，同场景有没有别人跟进。这是判断方法本身是否有效的唯一依据。网页上的"有价值 / 没价值"反馈保留，作为第二个依据。

### 网页

机会页按事件列出，每条显示场景、赢家、切口和状态。状态分三种：观察中、已应验、失效。

## 5. 不做什么

- 不再从需求聚类直接产机会卡。需求、提法、场景标签继续使用，作为证据和场景归类。
- 不估算下载量和收入的绝对值。
- 关键词热度和广告素材暂时不做。等前三步跑通后，再看值不值得接 Apple Search Ads。

## 6. 实现顺序

1. 写事件的 SQL，先出 E1 和 E2 的名单，人工看一遍，确认没有大量噪声（重新上架的、刷量的、大公司的）。
2. 卡片阶段改成以事件为输入，按第 4 节的字段生成。
3. 加预测日志表和 30 / 90 天的复核任务。
4. 网页的机会页按事件改版。
5. 本机定时任务改成跑新流程，再重新启用（2026-11-28 已停）。
