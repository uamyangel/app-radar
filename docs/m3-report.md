- **AI 摘要**：美国排名最靠前的 15 个 App 已经生成，例如 ChatGPT。
- **评论归类**：详情页「用户评论」上方是「评论在说什么」，点击类别可以筛选；每条评论旁边有标签，1–3 星的有中文要点。

## 做了什么

| 阶段 | 内容 | 频率 |
|---|---|---|
| classify | 每条评论打 1–2 个固定类别的标签（16 类），1–3 星加一句中文要点 | 每天，新评论优先 |
| summaries | App 周度摘要，字段严格按 SPEC 7.2 | 每周一；预算不够时后面几天补完 |
| briefs | 品类周度简报，字段严格按 SPEC 7.3 | 每周一，每个国家 × 21 个品类 |

**和 SPEC 的不同**
- **评论翻译改成了 AI 归类**：不在后台翻译评论（已确认），改为做归类。
- **模型**：用的是 `deepseek-flash`，已关闭思考模式。

**一些实现细节**
- **数字由程序算**：简报和摘要里的数字（新进榜、排名升降、低评分高排名、各类问题的条数和占比）都由程序先算好，模型只负责归纳和表述。
- **示例评论 ID 必须真实**：模型返回的示例评论 ID 和 App ID，不在输入里的会被过滤掉。
- **原因必须有依据**：提示词要求解释原因时必须有数据依据，例如版本更新时间。第一版简报里模型编过「可能因周末出行停车需求增加」这种外部原因，已经收紧。
- **预算控制**：当天累计估算费用达到 `daily_budget_cny` 就停止调用，剩下的留到第二天。三个国家的 job 并行运行时，各自每 30 秒把已花费用写进 `job_runs`，并读取当天的全局累计。
- **异常记录**：阶段内部没兜住的异常会记进 `job_runs` 并标成 failed，不再卡在 running 状态。
